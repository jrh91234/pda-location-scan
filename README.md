# PDA Location Scan

เว็บแอปสำหรับ **Zebra TN28** (Android 13): ใช้หัวสแกนของเครื่องสแกน QR สินค้า แล้วบันทึกว่าสินค้าอยู่ **Location** ไหน และลบรายการที่บันทึกผิดได้

- **หน้าเว็บ:** GitHub Pages (HTML/JS ล้วน ไม่ต้อง build)
- **ฐานข้อมูล:** Google Sheet (ชีต `Scans`)
- **Backend:** Google Apps Script (`appscript/`) ซึ่ง GitHub Actions จะ deploy ให้อัตโนมัติ (ใช้ระบบเดียวกับ WH-part-preparing)

---

## การใช้งานบนเครื่อง

**เมนู:** กดปุ่ม **☰** มุมซ้ายบนเพื่อเลือกหน้า (สแกน / กรอกเอง / ผัง / Kingdee / ประวัติ / ลบ / นับรูป / Scrap) หัวแถบแสดงชื่อหน้าปัจจุบัน ตัวเลขสีส้มบนปุ่ม ☰ = รายการที่ยังรอส่ง

1. เปิดเว็บใน Chromium บน TN28 แล้วใส่ **ชื่อผู้สแกน** (บังคับกรอก ระบบจำไว้ในเครื่อง)
   - **เลิกงาน:** กดที่ชื่อมุมขวาบน → **🚪 จบงาน (ออกจากระบบ)** ระบบจะล้างชื่อและรายการที่ยังไม่ได้กดบันทึก คนถัดไปต้องกรอกชื่อของตัวเองก่อนสแกน (รายการที่รอส่งยังส่งต่อด้วยชื่อคนเดิม)
   - ชื่อต้องยาวอย่างน้อย 2 ตัว และห้ามเป็น `0` / `00` / `-` (เครื่องที่ตั้งชื่อเป็น `0` ไว้ จะถูกบังคับให้กรอกชื่อใหม่)
2. **เลือก Location** ได้ 2 วิธี
   - สแกน QR/บาร์โค้ดของ Location (เช่น `CO-01-05A`) แอปจะรู้เองว่าเป็น Location
   - กดปุ่ม **เลือก Location** แล้วเลือก Zone (CO / CP / CQ) → Rack → ช่อง หรือพิมพ์ค้นหา
3. กดปุ่มสแกนข้างเครื่องเพื่อสแกน QR สินค้า รายการจะขึ้นในกรอบ **"สแกนแล้ว · ยังไม่บันทึก"** (ยังไม่ถูกบันทึก)
   - ถ้าสแกนใหม่อีกครั้ง รายการใหม่จะ **แทนที่** รายการเดิม ครั้งแรกจะไม่ถูกบันทึก
   - ตรวจรหัส Lot และจำนวน แล้วกด **💾 บันทึก → Location** (ถ้ายังไม่ได้เลือก Location ปุ่มจะพาไปเลือกก่อน)
   - เสียงสั้นเสียงเดียว = อ่าน/บันทึกสำเร็จ · เสียงต่ำสองครั้ง = ผิดพลาด (QR ผิดรูปแบบ, สแกนซ้ำ ฯลฯ)
4. Location จะค้างไว้ สแกนแล้วกดบันทึกต่อได้เรื่อยๆ จนกว่าจะเปลี่ยน Location

**กันสแกนติดกัน:** แอปไม่ต้องรอ Enter จาก DataWedge ถ้าตัวอักษรหยุดเข้ามา 0.35 วินาที ถือว่าสแกนจบ ถ้าอ่านค่าเดียวกันซ้ำ 2 รอบในครั้งเดียว (`ABCABC`) แอปจะตัดเหลือ 1 ถ้าเป็นป้าย Warehouse 2 อันต่างกันที่ติดกัน แอปจะไม่ยอมบันทึกและให้สแกนใหม่ นอกจากนี้แอปดึงโฟกัสกลับมาที่ช่องสแกนเสมอ Enter จากหัวสแกนจึงไม่ไปกดปุ่มอื่นแทน

แนะนำให้ตั้ง DataWedge → Barcode input → Reader params → **Same symbol timeout** ประมาณ 1000 ms ด้วย
5. **แก้ยอด:** กดที่ยอด (เช่น `144 EA ✏️`)
   - ก่อนบันทึก (ในกรอบสแกน หรือรายการที่ยัง "รอส่ง") แก้ได้เลย
   - หลังบันทึก แก้ได้จากรายการล่าสุดหรือหน้าประวัติ ต้องเลือกเหตุผล ระบบเก็บยอดเดิมครั้งแรก (`qty_original`) ผู้แก้ เวลา และเหตุผล (`edited_by`, `edited_at`, `edit_note`) ไว้ในชีต และแสดง "(เดิม …)" ในรายการ
6. **ย้าย Location:** กดที่ Location ของรายการ (เช่น `CO-01-01A ✏️`) แล้วเลือก Location ใหม่
   - รายการที่ยัง "รอส่ง" เปลี่ยนได้เลย
   - รายการที่บันทึกแล้ว ต้องเลือกเหตุผล (สแกนผิด Location / ย้ายของไปที่ใหม่ / อื่นๆ) ระบบเก็บ Location แรก (`location_original`) ผู้แก้ เวลา และเหตุผลไว้ และแสดง "(เดิม …)" ในรายการ คอลัมน์ location ในชีต `Photos` ของรายการนั้นจะอัปเดตด้วย
7. **ลบรายการที่ผิด:** กด **ลบ** ที่รายการล่าสุดในหน้าสแกน หรือที่หน้า **ประวัติ / ลบ** (ค้นหาตามวันที่ Location ผู้สแกน หรือรหัสสินค้าได้) แล้วเลือกเหตุผลก่อนยืนยัน

7.1 **เอาออกจาก Location (ของออกจริง ต่างจาก "ลบ" ที่ใช้แก้บันทึกผิด):**
   - หน้าสแกน → กด **📤 เอาออก** (ด้านบน) → สแกน QR กล่อง ระบบหาว่ากล่องอยู่ช่องไหน → ใส่จำนวน + เลือกเหตุผล (เบิกไปผลิต / ย้ายไปคลังอื่น / ส่งคืน Supplier / ของเสีย / อื่นๆ) → ยืนยัน · กด **📥 เก็บเข้า Location** เพื่อกลับโหมดปกติ
   - ช่อง **Job order / MO**: แตะเพื่อเลือกจาก Job ที่ **ยังไม่ปิด** (พิมพ์บางส่วนของเลข Job หรือรุ่นเพื่อกรอง) — ดึงจากชีต **Plan** ที่ระบบ Job order tracking ใช้ (CSV ที่ Publish ไว้, Status = Closed/Close/Archive ถือว่าปิด) ผ่าน Apps Script แคช 10 นาที · ยอด **ทำแล้ว** = ค่ามากสุดของ Actual, Actual Scan (ชีต Plan) และยอด FG Qty รวมจากแท็บ **ยอดผลิต** (ไม่นับ VOID และสแกนซ้ำวินาทีเดียวกัน) แบบเดียวกับ Job order tracking · เปลี่ยนแหล่งได้ด้วย Script Property `JOB_PLAN_CSV_URL` / `JOB_YOD_CSV_URL` · พิมพ์เลขที่ไม่อยู่ในรายการก็บันทึกได้ (มีคำเตือน) · เก็บในคอลัมน์ `out_job` และใน Log
   - หรือกด **📤 เอาออก** ที่กล่องในหน้าผัง (แตะช่อง) หรือปุ่ม **ออก** ในหน้าประวัติ
   - **จำนวน = ยอดในกล่อง** → เอาออกทั้งกล่อง (สถานะ `out` กล่องหายจากช่อง/ผัง/ยอดเทียบ Kingdee) · **น้อยกว่า** → เอาออกบางส่วน (ลดยอด กล่องยังอยู่ เก็บยอดเดิมใน `qty_original`)
   - ชีต `Scans` เพิ่มคอลัมน์ `out_by, out_at, out_reason, out_qty, out_job` · Log บันทึก `out` / `out_part` (ดูใน timeline และเล่นย้อนหลังบนผัง) · หน้าประวัติติ๊ก "แสดงที่ลบ / เอาออกแล้ว" เพื่อดูรายการที่เอาออก · กล่องที่เอาออกแล้ว สแกนเก็บเข้าใหม่ได้ (ไม่ถือว่าซ้ำ)
8. **ถ่าย/แนบรูป:** กด 📷 ที่รายการ (หรือปุ่ม "📷 ถ่ายรูปรายการนี้" ที่ขึ้นหลังสแกนสำเร็จ) เพื่อเปิดกล้อง กดชิป **🖼 n รูป** เพื่อดูรูป ลบรูป หรือ **เลือกจากเครื่อง** (เลือกได้หลายรูป)
   - แอปย่อรูปเป็น JPEG ด้านยาวไม่เกิน 1280px (ประมาณ 100–300KB) ก่อนส่ง
   - ไฟล์เก็บใน Google Drive โฟลเดอร์ **PDA Scan Photos** (ส่วนตัว ไม่เปิดสาธารณะ) และมีรายการในชีต `Photos` (`scan_id`, Location, รหัสสินค้า, ลิงก์ไฟล์)
   - ถ้าเน็ตหลุด รูปจะรอส่งในเครื่อง (IndexedDB) แล้วส่งให้อัตโนมัติ
   - การลบรูปจะย้ายไฟล์ไปถังขยะของ Drive (กู้คืนได้ภายใน 30 วัน) และทำเครื่องหมาย `deleted` ในชีต

### Export Excel
หน้า **ประวัติ / ลบ** → ตั้งตัวกรอง (วันที่ / Location / ผู้สแกน / ค้นหา / แสดงรายการที่ลบแล้ว) → กด **⬇️ Export Excel (ตามตัวกรอง)** จะได้ไฟล์ `.xlsx` (สูงสุด 20,000 แถว):
- ชีต **รายการ**: ทุกรายการตามตัวกรอง เรียงเก่า → ใหม่ พร้อมยอดเดิม/Location เดิม ผู้แก้ไข ผู้ลบ จำนวนรูป และ QR (มีตัวกรองหัวคอลัมน์)
- ชีต **สรุปตามพาร์ท**: รหัสสินค้า จำนวนกล่อง ยอดรวม หน่วย และ Location ที่อยู่ (เฉพาะรายการที่ใช้งาน)
- ไฟล์สร้างในเบราว์เซอร์ ใช้ได้ทั้งคอมฯ TN28 และโทรศัพท์ (ต้องต่ออินเทอร์เน็ต)

### ประวัติ (Timeline) ของแต่ละรายการ
ในหน้า **ประวัติ / ลบ** (และรายการที่บันทึกแล้วในหน้าสแกน) กดที่ **ชื่อพาร์ท 🕘** จะเปิด timeline เรียงตามเวลา: 🟢 บันทึก · 🔵 แก้ยอด (ค่าเดิม → ค่าใหม่) · 🟠 ย้าย Location · 🖼 แนบรูป / 🗑 ลบรูป · 🔴 ลบ พร้อมผู้ทำและเหตุผล
- กด **📦 ดูทุกกล่องของพาร์ทนี้** เพื่อดูทุกแพ็กเกจของรหัสสินค้าเดียวกันว่าอยู่ Location ไหน และยอดรวม แตะกล่องเพื่อดู timeline ของกล่องนั้น
- ทุกการเปลี่ยนแปลงเพิ่มแถวในชีต **`Log`** (เพิ่มอย่างเดียว ไม่แก้ย้อนหลัง): `log_id, at, scan_id, event, part_code, qr_raw, location_from, location_to, qty_from, qty_to, unit, by, note, ref`
- รายการที่บันทึกก่อนเริ่มมีชีต Log จะแสดงเหตุการณ์ย้อนหลังจากข้อมูลที่มี (ค่าแรก, แก้ครั้งล่าสุด, ลบ, รูป) และมีหมายเหตุ "ข้อมูลย้อนหลัง"

### ใช้ผ่านโทรศัพท์
เปิดลิงก์เว็บ (หรือสแกน QR ในหน้า ⚙ ตั้งค่า) แล้วกด **📸 สแกนด้วยกล้อง (โทรศัพท์)** ในหน้าสแกน ครั้งแรกเบราว์เซอร์จะขออนุญาตใช้กล้อง ให้กดอนุญาต จากนั้นเล็ง QR ให้อยู่ในกรอบ ผลที่อ่านได้เข้าขั้นตอนเดียวกับหัวสแกน PDA (สแกน Location = เปลี่ยน Location, สแกนสินค้า = ขึ้นกรอบรอบันทึก)
- ตัวอ่าน: Android Chrome ใช้ **ตัวอ่านในเบราว์เซอร์** · iPhone/อื่นๆ ใช้ **zxing** (WebAssembly, สำรองด้วย jsQR) และถ้าเปิดตัวอ่าน Apple ไว้ จะ **สลับใช้ Apple + zxing ทุกเฟรม** (ตัวไหนเจอก่อนใช้ตัวนั้น / ตัวที่ผิดพลาดติดกัน 5 ครั้งจะถูกปิด)
- ใต้ภาพกล้องแสดงข้อมูลวินิจฉัย: ความละเอียดกล้อง · ตัวอ่านแต่ละตัวอ่านไปกี่เฟรม · ผิดพลาดกี่ครั้ง (และข้อความ error)
- อ่านต่อเนื่องทุกเฟรม ขอภาพ 1920×1080 และอ่านเฉพาะกรอบกลางจอแบบเต็มความละเอียด (สลับอ่านทั้งภาพเป็นระยะ)
- ถ้าเครื่องรองรับ จะมีปุ่มซูม **1x / 1.5x / 2x / 3x** (จำค่าไว้) และ **🔦 ไฟฉาย** และตั้งโฟกัสต่อเนื่องให้
- **iPhone:** ถือห่าง QR ประมาณ **20–30 ซม.** (Safari ไม่สลับเลนส์มาโครให้ ถือใกล้จะเบลอ) ถ้ามีปุ่มซูมให้ใช้ 1.5x–2x
- **ใช้ตัวอ่านของ Apple (ทดลอง):** ตั้งค่า → Safari → ขั้นสูง → Feature Flags → เปิด **Shape Detection API** (ถ้ามีใน iOS รุ่นนั้น) แล้วเปิดเว็บใหม่ ใต้ภาพกล้องจะขึ้น "ตัวอ่าน: ตัวอ่านของ Apple (Shape Detection)" — เป็นฟีเจอร์ทดลอง อาจหายหลังอัปเดต iOS ไม่แนะนำให้พึ่งพาในเครื่องพนักงาน

### หน้า "กรอกเอง"
ใช้เมื่อป้ายเสีย / ไม่มี QR: เลือก Location แล้วกรอกรหัสสินค้า Lot Package จำนวน หน่วย จากนั้นกด **บันทึก**
- กด **📸 สแกนเติมข้อมูล** หรือสแกนป้ายใส่ช่องรหัสสินค้า ระบบจะแยกข้อมูลเติมให้ แล้วค่อยแก้ก่อนบันทึก
- รายการที่กรอกเองล้วนจะมี `qr_raw` ขึ้นต้นด้วย `MANUAL|` ในชีต ใช้แยกจากรายการที่สแกนได้

### แท็บ Kingdee: สรุปพื้นที่ Location
การ์ด **📦 พื้นที่ Location** ด้านบนแท็บ Kingdee: **ทั้งหมด** (Location ใน `js/locations.js`) · **ใช้แล้ว** = ช่องที่มีของใน Kingdee หรือมีกล่องที่สแกนในแอป (ไม่นับผู้บันทึกชื่อ test/ทดสอบ) · **ว่าง** = ไม่มีของทั้งสองระบบ · **ไม่นับ Public area** · ปุ่ม **รวม / ไม่รวม CO CP CQ** (จำค่าไว้ในเครื่อง) · กด "แยกตามโซน" ดูทีละโซน (ทั้งหมด / ใช้แล้ว / ว่าง / มีใน Kingdee / มีในแอป / %)

### หน้า "Scrap" (พาเลทเศษวัสดุ)
1. กด **＋ สร้างพาเลทใหม่** → เลือก **แผนก** (dropdown, บังคับ) ประเภท (เหล็ก / ทองแดง / พลาสติก / กระดาษ ฯลฯ) ที่มา/ไลน์ (ถ้ามี) และน้ำหนัก **kg** (ยังไม่ชั่ง เว้นว่างไว้ก่อนได้)
   - **รายชื่อแผนก** มาจากชีต `Departments` (คอลัมน์ `department`, `active`) — ผู้ดูแลวางรายชื่อแผนกที่คัดลอกจาก Kingdee ได้ (ระบบไม่ได้ต่อ Kingdee โดยตรง และไฟล์ยอดคงคลังที่ใช้อยู่ไม่มีข้อมูลแผนก) · ใส่ `active` = FALSE เพื่อซ่อนแผนกที่เลิกใช้ · เลือก "＋ เพิ่มแผนกใหม่…" ใน dropdown เพื่อเพิ่มจากหน้าเว็บ
   - เลขพาเลทออกให้อัตโนมัติ: **วันที่ (ววดดปปปป ค.ศ. เวลาไทย) - ลำดับของวันนั้น** เช่น `11062026-1`, `11062026-2` (เซิร์ฟเวอร์ออกเลข จึงไม่ซ้ำข้ามเครื่อง เลขที่ลบแล้วไม่นำกลับมาใช้) — ต้องต่ออินเทอร์เน็ตตอนสร้าง
2. **📷 ถ่ายรูป / 🖼 เลือกจากเครื่อง** แนบได้หลายรูป (ใช้ระบบรูปเดียวกับหน้าสแกน: ย่อรูป รอส่งเมื่อเน็ตหลุด เก็บใน Drive ชีต `Photos` location = `SCRAP`)
   - รูป Scrap เก็บในโฟลเดอร์ย่อย **Scrap Photos** ที่แชร์ให้ **ทุกคนที่มีลิงก์ดูได้** (ลิงก์ในไฟล์ Excel เปิดได้โดยไม่ต้องขอสิทธิ์) — ถ้านโยบายองค์กรไม่อนุญาตแชร์นอกโดเมน จะแชร์ให้ทุกคนในโดเมนแทน · รูปสินค้าจากหน้าสแกนยังเป็นส่วนตัว · รูป Scrap ที่อัปโหลดก่อนหน้านี้ถูกย้าย/แชร์ให้อัตโนมัติตอน Export Excel ครั้งแรก (หรือเมนู PDA Scan → แชร์รูป Scrap)
3. สถานะมี 2 แบบ: **📦 Stock** (อยู่ในโรงงาน ยังไม่ขาย — พาเลทใหม่ทุกพาเลท) **→ 🚚 ขายแล้ว** · ต้องมีน้ำหนักก่อนขาย (ยังไม่ชั่ง → ระบบให้ใส่น้ำหนักก่อน) · ข้อมูลเก่าที่เป็น "เปิดอยู่ / ปิดแล้ว" นับเป็น Stock ให้อัตโนมัติ
   - **ขายทีละพาเลท:** หน้าพาเลท → 🚚 ขาย / ส่งออก → ใส่เลขที่เอกสาร/ผู้รับซื้อ (ถ้ามี)
   - **ขายหลายพาเลทพร้อมกัน:** ปุ่ม **🚚 ขายหลายพาเลท** → ติ๊กพาเลทใน Stock (เลือกทั้งหมด / ตามประเภทได้ พาเลทที่ยังไม่ชั่งเลือกไม่ได้) → ใส่เลขที่เอกสาร/ผู้รับซื้อ (บังคับ) → ได้ **🧾 ใบส่งของ (PDF)** รวมทุกพาเลท + สรุปตามประเภท + ช่องเซ็น (พิมพ์ซ้ำได้จากหน้าพาเลทที่ขายแล้ว) · ถ้ามีพาเลทใดไม่พร้อมขาย ระบบไม่บันทึกเลยทั้งชุด
   - **พาเลทที่ขายแล้วถูกล็อก:** แก้น้ำหนัก / ข้อมูล / ลบไม่ได้ (ทั้งหน้าเว็บและเซิร์ฟเวอร์) ยังถ่ายรูปเพิ่มได้ · ถ้าขายผิด กด **↩️ ยกเลิกการขาย (คืนเข้า Stock)** (พาเลทหลุดจากใบส่งของเดิม ประวัติยังอยู่)
   - **📦 Stock ในโรงงาน:** การ์ดบนรายการแสดง kg และจำนวนพาเลทที่ยังไม่ขาย ทุกวันที่ ไม่ขึ้นกับตัวกรอง แยกตามประเภท และจำนวนที่ยังไม่ชั่ง
4. แก้น้ำหนักหลังบันทึกต้องเลือกเหตุผล ระบบเก็บน้ำหนักแรก (`weight_original`) · **ลบ** ได้จากปุ่ม "ลบ" ในรายการหรือในหน้าพาเลท (soft delete พร้อมเหตุผล) — **เลขที่ลบไม่นำกลับมาใช้**: มี -1 ถึง -4 ลบ -2 → พาเลทถัดไปคือ -5 (กันป้ายที่พิมพ์ไปแล้วซ้ำกับพาเลทใหม่) · ทุกการเปลี่ยนแปลงอยู่ในชีต `ScrapLog` (ดูได้จากปุ่ม 🕘 ประวัติ)
5. **🏷 ป้ายพาเลท (PDF)** ขนาด A6 มี QR ของเลขพาเลท ติดที่พาเลท → ในหน้า Scrap สแกนป้ายด้วยหัวสแกน PDA (หรือพิมพ์เลข) จะเปิดพาเลทนั้นทันที
6. **Export** ตามตัวกรอง (วันที่ / สถานะ / ประเภท / ค้นหา):
   - **Excel:** หัวตารางและชื่อชีตเป็น 3 ภาษา (ไทย / English / 中文) · ชีต พาเลท (พร้อมแผนก ชุดใบส่งของ ลิงก์รูปใน Drive) · สรุปตามประเภท · สรุปตามแผนก · สรุปรายวัน
   - **PDF:** รายงานสรุป + ตารางพาเลท + ช่องเซ็นชื่อ (เลือกแนบรูปของแต่ละพาเลทได้) · และ **📄 ใบพาเลท (PDF)** รายพาเลทพร้อมรูป
   - ถ้าโหลดตัวสร้าง PDF ไม่ได้ จะเปิดหน้าพิมพ์ของเบราว์เซอร์แทน (เลือก "บันทึกเป็น PDF")

คอลัมน์ชีต `Scrap`: `pallet_id, pallet_date, seq, created_at, created_by, device, scrap_type, source, weight_kg, note, status, updated_by, updated_at, weight_original, closed_by, closed_at, shipped_by, shipped_at, ship_ref, deleted_by, deleted_at, delete_reason, client_id, department, ship_batch`

### กติกาที่ระบบบังคับ
- **ลบแบบ soft delete:** แถวในชีตยังอยู่ แต่ `status = deleted` พร้อมบันทึกว่าใครลบ ลบเมื่อไร และเหตุผล จึงตรวจสอบย้อนหลังได้
- **QR ซ้ำ (ตรวจกับ cloud ทันทีหลังสแกน):** หลังสแกน ระบบเช็คกับชีตว่า QR นี้มีรายการที่ใช้งานอยู่หรือไม่ ถ้ามี กรอบรอบันทึกจะแสดง "QR นี้บันทึกแล้วที่ … โดย … เวลา …" พร้อมปุ่ม **📍 ย้ายมาที่ (Location ปัจจุบัน)** และ **ยกเลิก**
  - กดย้าย ระบบจะแก้ Location ของรายการเดิม (ไม่สร้างรายการใหม่) พร้อมเหตุผลและเก็บ `location_original`
  - ถ้าเน็ตหลุดตอนสแกนแล้วส่งภายหลังเจอซ้ำ รายการจะขึ้นสถานะ "ซ้ำ" พร้อมปุ่มย้าย / ยกเลิกเหมือนกัน
  - ถ้า QR เป็นรหัสสินค้าที่ใช้ซ้ำได้ ให้ตั้ง Script Property `ALLOW_DUPLICATE_QR = true`
- **รายการล่าสุดในหน้าสแกนซิงก์กับ cloud:** เก็บในเครื่องเพื่อให้เห็นทันทีและรองรับออฟไลน์ แต่ระบบดึงสถานะล่าสุดจากชีตตอนเปิดหน้า สลับแท็บ กลับมาที่แอป และทุก 1 นาที การลบ ย้าย หรือแก้ยอดจากเครื่องอื่นจึงขึ้นตรงกัน
- **เน็ตหลุด:** รายการจะเข้าคิว "รอส่ง" ในเครื่อง และส่งให้อัตโนมัติทุก 8 วินาทีเมื่อเน็ตกลับมา (ห้ามล้างข้อมูลเบราว์เซอร์ระหว่างที่ยังมีรายการรอส่ง) แต่ละรายการมี `scan_id` ที่เครื่องสร้างเอง ส่งซ้ำได้โดยไม่เกิดข้อมูลซ้ำ

### รูปแบบ QR ที่แยกข้อมูลให้อัตโนมัติ
| รูปแบบ | ตัวอย่าง |
|---|---|
| ป้าย Warehouse `รหัส*Lot*จำนวน*แพ็กเกจ` | `1005QT00197*2026083001*10*0002-2` |
| JSON | `{"materialCode":"X","lotNumber":"L1","quantity":5}` |
| ข้อความ `ชื่อ: ค่า` คั่นด้วย `\|` | `Material code: X\|Lot: L1\|Qty: 5` |
| อื่นๆ | เก็บข้อความทั้งหมดเป็นรหัสสินค้า |

ข้อความดิบจาก QR เก็บไว้ครบในคอลัมน์ `qr_raw` เสมอ

## ตั้งค่า DataWedge บน TN28 (ทำครั้งเดียวต่อเครื่อง)

ให้หัวสแกน "พิมพ์" ค่าที่สแกนลงช่องในหน้าเว็บ แล้วกด Enter ให้เอง

1. เปิดแอป **DataWedge** → เมนู ⋮ → **New profile** → ตั้งชื่อ `PDA Scan Web`
2. **Associated apps** → เพิ่มแอป **Chromium** (เลือก package ของ Chromium ที่มีในรายการ) → Activity `*`
3. **Barcode input** → Enabled → ใน **Decoders** ให้เปิด **QR Code** ไว้ (ถ้าป้าย Location เป็นบาร์โค้ด 1D ให้เปิด Code128 ด้วย)
4. **Keystroke output** → **Enabled**
   - **Basic data formatting** → Enabled → เปิด **Send data** และ **Send ENTER key**
5. **Intent output** → ปิด
6. ถ้าแอป Kingdee มี profile ของตัวเองอยู่แล้วก็ไม่ต้องแก้ เพราะ profile แต่ละตัวผูกกับแอปของตัวเอง

ทดสอบ: เปิดหน้าเว็บ แล้วสแกนป้าย Location ตัวอักษรจะขึ้นเป็น "📍 เปลี่ยน Location เป็น …"
ถ้าตัวอักษรหายบางตัว ให้ตั้ง **Keystroke output → Inter character delay** เป็น 10–20 ms

> ช่องสแกนตั้ง `inputmode="none"` ไว้ คีย์บอร์ดบนจอจึงไม่เด้งขึ้นมาบังหน้าจอ ถ้าป้ายเสียและต้องพิมพ์รหัสเอง ให้กดปุ่ม ⌨ ข้างช่องสแกน

## ตั้งค่าครั้งแรก (ผู้ดูแล)

### 1. Google Sheet + Apps Script
1. สร้าง Google Sheet ใหม่ชื่อ `PDA Location Scan`
2. เปิด **ส่วนขยาย → Apps Script** → วางโค้ด `appscript/code.gs` และเปิด "Show appsscript.json" แล้ววางเนื้อหา `appscript/appsscript.json`
3. กลับไปที่ชีตแล้วรีเฟรช จะมีเมนู **PDA Scan** → กด **ตั้งค่าเริ่มต้น** → อนุญาตสิทธิ์ (ขั้นสูง → ไปที่ … → อนุญาต) ระบบจะสร้างชีต `Scans` ให้
4. Apps Script → **Deploy → New deployment → Web app**: Execute as **Me**, Who has access **Anyone** → คัดลอก URL `/exec`
5. นำ URL ไปใส่ใน `js/config.js` (`API_URL`) แล้ว commit
6. Script Properties ที่ใส่เพิ่มได้ (ไม่บังคับ)
   - `SPREADSHEET_ID`: ใช้เมื่อ script ไม่ได้ผูกอยู่กับชีต
   - `ALLOW_DUPLICATE_QR`: `true` = ยอมให้ QR ซ้ำได้

### 2. GitHub (deploy อัตโนมัติ)
1. สร้าง repo (เช่น `jrh91234/pda-location-scan`) แล้ว push โค้ดขึ้น branch `main`
2. **Settings → Pages** → Source: Deploy from branch → `main` / root
3. ตั้ง Secrets 3 ตัวสำหรับ `.github/workflows/deploy-appscript.yml`
   - `APPS_SCRIPT_ID`: ดูได้จาก Apps Script → Project Settings → Script ID
   - `APPS_SCRIPT_DEPLOYMENT_ID`: ดูได้จาก Deploy → Manage deployments (ID ของ deployment ในข้อ 1.4)
   - `CLASPRC_JSON`: ใช้ไฟล์เดียวกับ repo อื่น
     ```bash
     gh secret set CLASPRC_JSON --repo jrh91234/pda-location-scan < ~/.clasprc.json
     ```
4. ต่อไปเมื่อ push การแก้ใน `appscript/` GitHub Actions จะอัปเดต deployment เดิมให้ URL `/exec` คงเดิม

## อัปเดตหน้าเว็บ (สำคัญ)

ทุกครั้งที่แก้ไฟล์หน้าเว็บ (`index.html`, `js/`, `css/`) ให้รันคำสั่งนี้ก่อน commit
```bash
python tools/bump-version.py
```
คำสั่งนี้ตั้งเลขเวอร์ชันใหม่ (แสดงเป็น `vYYYYMMDD-HHMM` ข้างชื่อ PDA Scan) เครื่อง PDA ที่เปิดเว็บค้างไว้จะเช็ค `version.json` ทุก 1 นาที ถ้าเจอเวอร์ชันใหม่จะโหลดหน้าใหม่เองตอนที่ไม่มีงานค้าง จึงไม่ต้องรอ cache ของ GitHub Pages ที่เก็บไว้ 10 นาที

เซิร์ฟเวอร์ (Apps Script) ตรวจ QR ซ้ำอีกชั้น: ข้อความเบิ้ล `ABCABC` จะถูกตัดเหลือ `ABC` และป้าย Warehouse 2 อันที่ติดกันจะไม่ถูกบันทึก ถึงเครื่องจะยังเปิดหน้าเว็บเวอร์ชันเก่าอยู่ก็ตาม
